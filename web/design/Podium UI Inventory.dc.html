LayerRow

<LayerRow layer ownership readOnly dragging>

Source type is pluggable, so an unknown type still renders: generic chip, details behind a disclosure, actions unchanged. Visibility renders one marker per matching axis in a fixed order — public, organization, groups, then users — and an axis naming more members than the row holds summarises the remainder inside its own marker, so no axis is dropped. Ownership is a marker rather than a gate: a row the caller does not own keeps its write controls and presents whatever refusal the write receives, and only the read-only mode mutes the controls. The ownership prop is three-valued — mine, elsewhere, and none — and it is read only on a user-defined row, where the marker compares the row's stored owner against the caller's own subject and the posture read reports a subject only where one resolves. On an admin-defined row, and on any row where no subject resolved, the prop takes none and the row carries no ownership marker: an admin-defined layer's stored owner is supplied by the caller who registered or patched it and names no authorized subject, so the row shows that field and asserts nothing about who may write it. A refusal a write receives is drawn on the row and on the action that was attempted, and it reuses neither the ownership marker nor the session-expiry dialog, because it carries neither meaning.

RULES THAT KEEP THE SET SMALL
One row component per entity
ArtifactRow and LayerRow cover the catalog entities, and PaletteRow is ArtifactRow at palette density. DataTable's other rows — resources, reingest outcomes, restores — are plain cells over the shared column grid, not new components.
Badges never branch on meaning
A badge takes a tone, not a domain concept. Type, version, visibility, provenance, and error codes all reuse it.
One feedback container
Banner carries tone and scope. PageBanner and InlineError are presets over it, not separate implementations.
Density is a prop, not a component
SubdomainCard has two densities; ArtifactRow has comfortable and palette. Resist a second card when a list grows.
Counts come from one component
Every "N of M" is a ResultCount. Four surfaces report the same query differently the moment they each format their own.
A result you must read is not a toast
Reingest returns rejections and conflicts that need action, so it resolves into a Modal. Toasts are for things safe to miss — and nothing here is.
Nothing fetches
Every component takes data as props. Loading and error states are passed in, so a screen owns the request and the component owns the appearance.
Absent is a state, not a blank
Optional fields — description, keywords, version, score, sensitivity, relations, resources — each have a designed absent state. Not-found and not-permitted share one, deliberately.

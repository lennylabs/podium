- **Workspace local overlay precedence test**: confirm the workspace local overlay overrides every registry-side layer for a synthetic conflicting artifact, with the overlay artifact served as authored, and that removing the overlay file restores the registry-side artifact.

- **Domain composition tests**: `DOMAIN.md` `include:` patterns surface matching artifacts; recursive `**` and brace `{a,b}` patterns resolve correctly; `exclude:` removes paths; `unlisted: true` removes a folder and its subtree from `load_domain` enumeration; `DOMAIN.md` from multiple layers merges per §4.5.4; remote-vs-local glob resolution asymmetry is correct.

- **Cross-layer import tests**: a `DOMAIN.md` ingested in one layer imports an artifact ingested in another; a caller who can see both layers sees the imported artifact; a caller who can see only the destination layer sees nothing for that import; imports that don't currently resolve produce an ingest-time warning, not an error.

- **Materialization test**: exercise `load_artifact` against artifacts with diverse bundled file types (Python script, Jinja template, JSON schema, binary blob, external resource); verify atomic write semantics; verify partial-download recovery; verify presigned URL refresh on expiry.

- **MaterializationHook chain test**: configure two hooks in order; the second receives the first's output; each hook can rewrite a file, drop a file, or emit a warning; the final atomic write reflects the chain's combined output. - **Web UI verification matrix**: the web UI (§13.10) is verified against a matrix carrying one cell per unit, obligation kind, and driver, and a cell is present exactly when the unit carries an obligation of that kind on that driver. A unit is a surface the web UI design brief at `web/DESIGN.md` names under its surfaces heading, or the single statement of what a request the browser issues receives or of what the page renders, wherever the change implementing the web UI states it. A surface unit's statement is that surface's section in the brief under the surfaces heading, so every unit has a statement its cells cite. A statement unit is the single statement of the behavior it fixes, and any other site carrying that behavior restates it from there and moves with it. Both sets are enumerable: the brief fixes its surfaces, and each behavior the web UI fixes is stated once in a site that forbids restatement elsewhere. A browser-observable behavior with no unit is therefore a behavior with no single statement, and a surface the brief adds under its surfaces heading and a statement added later each carry their cells with them. The surfaces the brief names today are the domain browser, search, the artifact viewer, similarity, usage, and the layer panel, and the statements the predicate admits today are the browser-session, authentication-route, layer-write authorization, and rendering rules in §6.3.3, §6.3.4, §6.10, §7.3.1, §7.3.4, §8.7, and §13.10, together with the rules the same change states for behavior those sections leave to it, such as how the page renders an untrusted artifact body. That derivation is worked here for the reader and decides nothing: a unit the predicate admits is a unit whether or not it is named here, and a name here the predicate does not admit is a defect in this sentence rather than a unit. The obligation kinds are Read (a request that leaves registry state as it found it), Write (a request that changes it), Error (the refusal or failure arm of either), and Render (what the human is shown). An obligation concerns what a request receives or what the page renders, and a request either changes registry state or does not and takes either its success arm or its refusal or failure arm, so the kinds cover every obligation a unit carries; a cell is absent where the unit carries no obligation of that kind. A request is server-driven when the test constructs it and browser-driven when the built bundle's own client code issues it; a statement carrying both halves is driven both ways, and the §6.3.4 browser-origin gate is server-driven only. Each cell is driven at every condition point the statement it cites ranges over, meaning the values of each variable that statement's own text branches on. A statement is the single statement of its behavior, so it carries its own branches and no other site adds one. A cell names its unit's statement, gives the condition points it is driven at, and states no condition, field, status, code, or value that statement does not carry. Where a statement leaves a value to the deployment or to the implementation, the cell states the obligation over its condition points, names no value, and the test establishes the value. Where a statement fixes the value, such as the HTTP method a route answers on, the cell cites that statement and restates no value, so each value is stated in exactly one place. A variable a statement does not branch on generates no point for that statement's cells, and a variable a statement branches on generates its points whether or not that variable is named here. The variables that recur across statements today are the location the credential arrives in, the browser flow enabled or disabled, whether the deployment serves the web UI, the identity posture, the caller's standing, the registry's §13.2.1 write mode, the browser-origin evidence the gate branches on, and, on an Error cell whose statement turns on a dependency the registry called, whether that dependency answered. The matrix excludes the bundle build and its embedding in the server, whose verification is separate, and it does not reach the startup configuration guard, its ordering, the redirect-URI conjunct, or the rule placing the configuration keys, whose verification is likewise separate, because each states what the process does before it serves a request and no request the browser issues observes it. Two obligations stay named, each for its own reason. A sign-out refused by the browser-origin gate clears nothing, which is the composition of two units; it is asserted on the Write cell of the §7.3.4 cookie statement at the CSRF-refusal condition point. The search unit's Render cell is driven with the optional result fields, the relevance score and the sensitivity label, both present and absent; the search statement branches on neither field, so this is the one cell driven at a condition point its own statement does not carry.
